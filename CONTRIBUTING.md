# Contributing

Thanks for your interest in improving tauri-plugin-voip-push!

## Layout

| Path | What |
|---|---|
| `src/` | Rust plugin layer (commands, mobile bridge, desktop no-ops) |
| `ios/Sources/` | Swift: APNs/PushKit registration + CallKit |
| `android/src/main/` | Kotlin: FCM + Telecom/ConnectionService + CallStyle notification |
| `guest-js/` | Typed JavaScript bindings |
| `permissions/default.toml` | Tauri permission sets (autogenerated files are not committed) |

## Building & testing

- **Rust:** `cargo check`, `cargo test`, `cargo fmt --all -- --check`,
  `cargo clippy --all-targets -- -D warnings`. Mobile targets:
  `cargo check --target aarch64-apple-ios` (macOS) /
  `--target aarch64-linux-android`.
- **guest-js:** `cd guest-js && pnpm install && pnpm build`.
- **Swift / Kotlin:** compiled as part of a consuming Tauri app
  (`tauri ios build` / `tauri android build`) — the standalone Gradle and
  SwiftPM projects depend on files the Tauri CLI copies in at app build
  time. End-to-end testing requires a Firebase project (Android) and an
  APNs VoIP certificate/key (iOS).

## Conventions

- Never log or `toString()` a join token — redact it.
- Every terminal call path on Android must funnel through
  `IncomingCallManager.cleanUp` so no ring surface leaks.
- Every iOS VoIP push must report a call to CallKit — even malformed ones
  (Apple terminates apps that don't).
- Keep the payload contract and both native implementations in sync with
  the README table.

## Pull requests

Run the Rust checks above before opening a PR, describe the behavior
change, and update `CHANGELOG.md` under `[Unreleased]`.
